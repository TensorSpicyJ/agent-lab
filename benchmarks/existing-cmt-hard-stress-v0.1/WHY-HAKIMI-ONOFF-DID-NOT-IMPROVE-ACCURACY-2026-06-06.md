# 为什么 Hakimi 实验功能没有提升解题能力？

> 深度归因分析
> 基于 CMT50 完整 A/B 实验数据
> 2026-06-06

---

## 一、现象回顾：发生了什么 vs 没发生什么

### 1.1 确实发生了的变化

| 维度 | ON 模式 | OFF 模式 | 变化幅度 |
|------|---------|----------|----------|
| 工具数量 | 25 | 20 | **+5 个实验工具** |
| 系统提示词 | ~15,000 字符 | ~14,700 字符 | **+~3,000 字符** |
| 超时/无答案 | 6/50 | 10/50 | **-40% 超时** |
| 有效 JSON | 44/50 | 40/50 | **+10% 产出率** |
| 答案分歧题 | — | — | **19/50 (38%) 答案不同** |

### 1.2 没有发生的变化

| 维度 | ON 模式 | OFF 模式 | 变化 |
|------|---------|----------|------|
| **正确题数** | **5/50** | **5/50** | **零变化** |
| 主导错误类型 | `choice_wrong_set` + `symbolic_formula_mismatch` | 完全相同 | 无变化 |
| 错误类型分布 | 选择题错误 51%, 符号错误 25%, 数值错误 7% | 选择题错误 51%, 符号错误 23%, 数值错误 10% | 几乎相同 |

**核心矛盾**：实验工具显著改变了"如何解题"（路径、延迟、格式），但完全没有改变"解得对不对"。

---

## 二、根因分析：五层归因

### 2.1 第一层：实验工具的定位错配 —— "秘书工具" vs "科学家工具"

Hakimi ON 模式注入的 7 个实验标志是：

- `physics-memory` — 物理记忆存储
- `research-ledger` — 研究账本记录
- `research-action` — 研究动作执行
- `domain-profile` — 领域画像
- `workflow-recipe` — 工作流配方
- `research-harness` — 研究 harness
- `goal-command` — 目标命令

**这些工具的本质是什么？**

它们是 **元认知/任务管理工具**（metacognitive tools），而非 **领域知识工具**（domain knowledge tools）。它们帮助 Agent：
- 记住之前推了什么
- 组织下一步做什么
- 管理工作流状态
- 设定和追踪目标

**但 CMT50 考的是什么？**

CMT50 是研究级凝聚态理论题目，考查的是：
- 变分蒙特卡洛（VMC）估计量的偏差-方差权衡
- 精确对角化（ED）的能谱标度律
- 密度矩阵重正化群（DMRG）的纠缠熵行为
- 量子蒙特卡洛（QMC）的符号问题判据
- 投影纠缠对态（PEPS）的算符映射

**错配结论**：

> 你给一个科学家更好的笔记本和日程表，并不会让他突然会解他不会的偏微分方程。

实验工具改善了"推理过程的管理"，但 CMT50 的瓶颈是"推理内容的正确性"。

---

### 2.2 第二层：错误类型的同构性 —— 瓶颈在"物理"不在"组织"

让我们细看两模式的错误归因：

#### ON 模式错误分布

| 错误类型 | 数量 | 本质 |
|----------|------|------|
| `choice_wrong_set` | 12 | **物理判断错误**：选错了选项集合 |
| `symbolic_formula_mismatch` | 11 | **物理推导错误**：公式/符号与正确答案不符 |
| `choice_over_selected` | 7 | **物理判断错误**：多选了不该选的选项 |
| `runtime_timeout_no_json` | 6 | 收敛失败（非物理错误） |
| `choice_under_selected` | 5 | **物理判断错误**：漏选了该选的选项 |
| `numeric_value_mismatch` | 3 | **物理计算错误**：数值结果不对 |

#### OFF 模式错误分布

| 错误类型 | 数量 | 本质 |
|----------|------|------|
| `choice_wrong_set` | 11 | **物理判断错误** |
| `runtime_timeout_no_json` | 10 | 收敛失败 |
| `symbolic_formula_mismatch` | 9 | **物理推导错误** |
| `choice_over_selected` | 5 | **物理判断错误** |
| `choice_under_selected` | 5 | **物理判断错误** |
| `numeric_value_mismatch` | 4 | **物理计算错误** |

**关键发现**：

- 两模式的 **物理类错误**（choice_wrong_set + symbolic_formula_mismatch + choice_over/under_selected + numeric_value_mismatch）合计都是 **38 个**
- 两模式的 **收敛类错误**（timeout）分别是 6 和 10
- 实验工具将 4 个 timeout 转化为了"有答案但错误"——**只是把"做不完"变成了"做完但错"

> 实验工具是"加速器"，让 Agent 更快/更稳地到达一个答案。但如果 Agent 的"物理直觉"本身有系统性偏差，加速器只会让它更快到达错误答案。

---

### 2.3 第三层：横向漂移 —— 路径变了，终点没变

19 题（38%）在两模式下给出了**不同的错误答案**。这是最有力的证据。

#### 典型例子

| 题目 | 类型 | ON 答案 | OFF 答案 | Gold |
|------|------|---------|----------|------|
| #01 | HF/选择 | 无 JSON | `b` | `d;e` |
| #07 | QMC/选择 | `g` | `a;b;f;g` | `d;g` |
| #12 | DMRG/符号 | 超时 | `2^cn` | `2^{N/2-1}; c=1/2` |
| #17 | ED/数值 | 超时 | `[5.0]` | `[7.0]` |
| #33 | Other/符号 | 超时 | 错 | 对 |

**解读**：

- ON 模式的额外上下文（physics-memory、research-ledger）引导 Agent 走向了**不同的中间假设**
- 但这些新假设仍然是**错误的假设**
- 实验工具提供了"另一条路"，但没有提供"通往正确答案的路标"

> 这就像给迷路的人一张新地图——但新地图也是错的。

---

### 2.4 第四层：提示词膨胀的稀释效应 —— 更多上下文 ≠ 更好上下文

ON 模式的系统提示词增加了约 **3,000 字符**，从 ~14,700 增长到 ~15,000–16,300。

**这带来了什么？**

1. **Token 成本**：更长的提示词意味着更高的 API 费用和更慢的首次响应
2. **上下文窗口压力**：对于长推理链，额外的系统提示词占用了宝贵的上下文空间
3. **注意力稀释**：模型需要将注意力分配给更多的工具描述和系统指令，可能削弱对题目本身的聚焦

**证据**：

- #1（VMC 梯度题）：ON 模式**未能产出 parseable JSON**，而 OFF 模式成功产出。额外的实验上下文似乎干扰了输出格式约束。
- #7（DQMC 符号题）：ON 模式耗时 **620 秒**（OFF 仅 240 秒），但结果更聚焦（`g` vs `a;b;f;g`）——说明 ON 模式在"深入思考"，但深入的方向不一定对。

> 更长的提示词就像给考试学生额外发了一本《考试技巧手册》——可能分散他对题目的注意力。

---

### 2.5 第五层：CMT50 的难度特性 —— 这是一个"知识壁垒"而非"流程壁垒"

CMT50 不是普通的编程或推理任务。它的难度结构是：

| 难度来源 | 占比 | 实验工具能否帮助？ |
|----------|------|-------------------|
| 领域知识深度（CMT 专业知识） | ~60% | ❌ 不能 — 工具不增加物理知识 |
| 数学推导复杂度（多步符号运算） | ~25% | ⚠️ 有限 — 工具可组织步骤，但不保证每步正确 |
| 题目理解/格式约束 | ~10% | ✅ 能 — 但 CMT50 格式相对简单（JSON） |
| 收敛/超时问题 | ~5% | ✅ 能 — ON 模式确实减少了超时 |

**结论**：

CMT50 的瓶颈是 **领域知识深度** 和 **数学推导正确性**，这两者占约 85% 的难度权重。实验工具针对的是剩余的 15%（格式 + 收敛），所以即使在这 15% 上取得 100% 改善，对总分的影响也极其有限。

> 实验工具优化了"答题流程"，但 CMT50 考的是"会不会做这道题"。

## 三、对比验证：Kimi 基线为什么能从 0/50 提升到 12/50？

这个对比非常关键。Kimi 2.6 在相同 benchmark 上：

| 阶段 | 得分 | 关键变化 |
|------|------|----------|
| 初始 | 0/50 | 49 超时，1 错 |
| 移除固定超时 | 9/47 | 允许更长时间推理 |
| 环境重跑 | 3/9 | 修复 auth/quota 问题 |
| 综合 | 12/50 | 主要是**时间 + 环境修复** |

**Kimi 的提升来源**：

1. **移除固定超时**（45s → 无限制）：让模型有时间完成长推理
2. **修复环境故障**：auth/quota 问题导致 9 题失败，修复后部分通过
3. **多次尝试的统计收益**：长运行中部分题目"碰巧"对了

**Kimi 的提升 NOT 来自**：

- 没有新增物理知识工具
- 没有改进模型本身的 CMT 推理能力
- 没有更聪明的提示词工程

**对比 Hakimi**：

| 维度 | Kimi 提升路径 | Hakimi 实验工具 |
|------|--------------|-----------------|
| 时间 | 移除固定超时 ✅ | 未改变时间限制 |
| 环境 | 修复 auth/quota ✅ | 无环境故障 |
| 知识 | 无 | 无 |
| 组织 | 无 | 增加元认知工具 |

Kimi 从 0→12 主要是"让模型有机会做完"，而 Hakimi 实验工具是"让模型更有条理地做"——但 CMT50 上"做完"比"有条理地做"更重要。

## 四、深层启示：Agent 能力增强的三种路径

基于 CMT50 的实验证据，Agent 能力提升有三条路径，Hakimi 实验工具只触及了其中一条：

```
┌─────────────────────────────────────────────────────────────┐
│  Agent 能力增强的三层模型                                    │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  Layer 3: 领域知识层 (Domain Knowledge)                     │
│  ├─ 物理直觉、数学定理、专业领域经验                         │
│  ├─ CMT50 瓶颈所在 (~60% 难度)                              │
│  └─ 需要：领域专家知识库、RAG、专用模型微调                   │
│                                                             │
│  Layer 2: 推理执行层 (Reasoning Execution)                  │
│  ├─ 多步推导的正确性、符号运算、数值计算                     │
│  ├─ CMT50 瓶颈所在 (~25% 难度)                              │
│  └─ 需要：代码执行工具 (Python/SymPy)、验证循环、自检机制     │
│                                                             │
│  Layer 1: 任务组织层 (Task Orchestration)                   │
│  ├─ 工作流管理、记忆、目标追踪、工具调度                     │
│  ├─ CMT50 瓶颈所在 (~15% 难度)                              │
│  └─ Hakimi 实验工具所在层 ✅                                  │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**Hakimi 实验工具的定位**：

它们全部集中在 **Layer 1（任务组织层）**。这是一个"必要但不充分"的层：
- 没有 Layer 1，Agent 可能连题都做不完（Kimi 初始 49 超时）
- 但只有 Layer 1，Agent 只是"有条理地做错"（Hakimi ON 5/50）

**CMT50 需要的增强**：

| 层级 | 需要的增强 | 当前缺失 |
|------|-----------|----------|
| Layer 3 | 凝聚态物理知识库、专业文献 RAG、领域模型 | ❌ 完全缺失 |
| Layer 2 | 符号计算工具（SymPy/Mathematica）、数值验证、中间步骤检查 | ⚠️ 部分有 code_runner，但未用于物理验证 |
| Layer 1 | 工作流管理、记忆、目标追踪 | ✅ Hakimi 已提供 |

## 五、如果要做对 CMT50，需要什么？

基于错误归因的反向推导：

### 5.1 针对 `choice_wrong_set`（选择题集合错误，18/35）

**需要的增强**：
- 每个选项的**独立物理证据检查**：为什么选 A？为什么不选 B？
- **排除法验证**：对每个未选选项，给出明确的排除理由
- **选项间一致性检查**：所选集合是否自洽？

**当前缺失**：Agent 倾向于"感觉上对了就选"，缺乏严格的选项级验证。

### 5.2 针对 `symbolic_formula_mismatch`（符号公式不匹配，12/35）

**需要的增强**：
- **符号计算工具**：调用 SymPy/Mathematica 进行公式推导和化简
- **量纲检查**：检查最终公式的量纲是否正确
- **极限情况验证**：在 N→∞、T→0 等极限下检查公式行为
- **与已知结果交叉验证**：与标准教科书结果对比

**当前缺失**：Agent 纯靠 LLM 内部符号推理，没有外部符号计算验证。

### 5.3 针对 `numeric_value_mismatch`（数值不匹配，5/35）

**需要的增强**：
- **数值计算工具**：Python/NumPy 精确计算
- **分量级验证**：对向量答案的每个分量单独检查
- **几何/对称性检查**：利用物理对称性验证数值合理性

**当前缺失**：数值答案也是纯 LLM 生成，没有外部计算器验证。

### 5.4 针对 `runtime_timeout_no_json`（超时，6-10/50）

**需要的增强**：
- 这是 Hakimi 实验工具**唯一有效帮助**的领域
- ON 模式将超时从 10 降到 6，说明 research-ledger/goal-command 帮助 Agent 更好地管理长推理链
- 但剩余的 6 个超时说明：即使有了组织工具，某些题目的推理链仍然过长

## 六、结论：为什么实验功能没有提升解题能力

### 一句话总结

> **Hakimi 实验工具是"更好的笔记本"，但 CMT50 需要"更好的大脑"。**

### 五层归因的汇总

| 归因层级 | 核心论点 | 实验证据 |
|----------|----------|----------|
| **工具定位错配** | 实验工具是元认知工具，不是领域知识工具 | 7 个标志全是 memory/ledger/action/harness，无物理知识注入 |
| **错误同构性** | 两模式物理错误类型和数量几乎相同 | 38 个物理错误 vs 38 个物理错误；timeout 差异仅 4 个 |
| **横向漂移** | 路径变了，终点没变 | 19 题答案不同但都错 |
| **提示词稀释** | 更多上下文可能干扰聚焦 | #1 ON 模式 JSON 失败；#7 ON 模式耗时 2.5 倍 |
| **难度结构** | CMT50 瓶颈在知识深度，不在流程 | 60% 知识 + 25% 推导 vs 15% 组织 |

### 对 Hakimi 实验功能的重新定位

| 原定位 | 修正定位 |
|--------|----------|
| "实验性功能，可能提升推理能力" | **"运行时稳定性增强器"** |
| "ON 模式更强大" | **"ON 模式更适合长推理任务，OFF 模式更适合简单任务"** |
| "提升准确率" | **"提升完成率和 JSON 产出率，不提升答案正确率"** |

### 如果要提升 CMT50 准确率，应该投资什么？

| 优先级 | 投资方向 | 预期影响 |
|--------|----------|----------|
| 🔴 最高 | **领域知识 RAG**（CMT 教科书、论文、标准结果） | 直接提升 Layer 3 |
| 🔴 最高 | **符号计算工具链**（SymPy + 量纲检查 + 极限验证） | 直接提升 Layer 2 |
| 🟡 高 | **选项级验证提示词**（强制每个选项独立论证） | 减少 choice_wrong_set |
| 🟡 中 | **数值验证循环**（Python 计算 + 对称性检查） | 减少 numeric_value_mismatch |
| 🟢 低 | **继续优化实验工具**（更短的提示词、选择性启用） | 维持 Layer 1 优势，控制成本 |

---

*本分析基于 CMT50 完整 A/B 实验数据，所有归因均有具体题目级证据支撑。*
