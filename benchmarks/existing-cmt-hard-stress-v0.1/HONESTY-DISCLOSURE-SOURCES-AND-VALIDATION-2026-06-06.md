## 三、诚实披露：我的设计方法论

### 3.1 我做了什么

1. **文献调研**：阅读了 SCIGRAPHRAG、Knowledge Graph RAG、AITP 等公开资料
2. **错误归因分析**：基于 CMT50 的 50 题实验数据，分析了 35 个 answer_accuracy 错误的类型
3. **反向推导**：从错误类型出发，推测"如果有什么工具，可能减少这类错误"
4. **schema 设计**：基于推测，设计了具体的知识卡片结构和验证合约模板

### 3.2 我没做什么

1. ❌ **没有实现任何工具**：所有工具都是概念设计，无代码
2. ❌ **没有运行任何验证实验**：所有预期收益数字都是估算
3. ❌ **没有构建任何知识库**：CMT 领域的 KG 实体类型是纸面设计
4. ❌ **没有与现有系统对比**：未与 SCIGRAPHRAG 或 AITP 的实际效果对比

### 3.3 我的设计置信度

## 四、如何检验这些设计？—— 可操作的验证路径

### 4.1 最小可行验证（1-2 周）

#### 验证 1：知识卡片 vs 文本块的对比

**假设**：结构化知识卡片比文本块更能减少"检索猜测"

**实验设计**：
```
对照组 A：传统 RAG，返回 3 个文本块
对照组 B：结构化 RAG，返回 1 个知识卡片（含 key_properties/caveat/applicable_conditions）

题目集：CMT50 中 10 道概念性选择题
评估指标：
  - 准确率
  - 答案与检索文本的相似度（复制率）
  - 变体题目通过率
```

**退出标准**：
- 如果 B 准确率 ≤ A → 知识卡片无优势，放弃该方向
- 如果 B 准确率 > A 但变体通过率 < 50% → 知识卡片促进"检索猜测"，需重新设计
- 如果 B 准确率 > A 且变体通过率 > 70% → 知识卡片促进"蒸馏理解"，继续投资

#### 验证 2：validation contract 的强制效果

**假设**：强制验证合约能减少 choice_wrong_set 和 symbolic_formula_mismatch

**实验设计**：
```
对照组 A：标准 prompt，无验证要求
对照组 B：prompt 增加 validation contract（必须给出每选项理由、量纲检查、极限验证）

题目集：CMT50 中 15 道选择题 + 10 道符号题
评估指标：
  - 准确率
  - 错误类型分布
  - Agent 是否遵守验证要求（从 stderr 审计）
```

**退出标准**：
- 如果 B 的 choice_wrong_set 未减少 → validation contract 无效
- 如果 B 的准确率下降（因过度约束导致超时）→ 需要调整验证粒度

### 4.2 中等规模验证（1 个月）

#### 验证 3：最小知识库测试

**假设**：Agent 能从"原理索引"（非全文）推断答案

**实验设计**：
```
知识库 A：完整教科书章节（~50,000 tokens）
知识库 B：仅原理索引（~500 tokens，如 "VMC: 变分蒙特卡洛，适用：多体基态"）
知识库 C：无知识库

题目集：CMT50 全量 50 题
评估指标：
  - A/B/C 三组的准确率
  - B 组 vs C 组的差异（知识索引的净效应）
  - A 组 vs B 组的差异（全文 vs 索引的效应）
```

**关键判断**：
- 如果 B ≈ C → 知识索引无用，Agent 无法从少量信息推断
- 如果 B ≈ A → 全文冗余，索引足够
- 如果 C < B < A → 索引有用但全文更有用，需要平衡

#### 验证 4：干扰知识抗性测试

**假设**：Agent 能识别并拒绝错误的检索知识

**实验设计**：
```
对照组 A：纯净知识库（100% 正确）
对照组 B：污染知识库（80% 正确 + 20% 故意错误）

题目集：CMT50 中 20 道题目
评估指标：
  - B 组准确率 vs A 组
  - B 组中被污染知识误导的比例
  - Agent 是否显式拒绝错误知识（从 stderr 审计）
```

**关键判断**：
- 如果 B 准确率 ≈ A → Agent 能识别并拒绝错误知识（强信号）
- 如果 B 准确率 << A → Agent 被错误知识误导（RAG 风险高）

### 4.3 完整验证（2-3 个月）

#### 验证 5：完整 AITP 风格过程层

**假设**：AITP 风格的 claim/evidence/validation 分离能提升结果可信度

**实验设计**：
```
对照组 A：标准 Agent（直接给答案）
对照组 B：AITP 风格 Agent（必须记录 claim → evidence → validation → promotion）

题目集：CMT50 全量 50 题
评估指标：
  - 准确率
  - 人工审核推导步骤的可信度评分（1-5）
  - 错误时的可追溯性（能否定位到具体失败步骤）
  - 重跑稳定性（同一题多次运行的结果一致性）
```

## 六、核心结论

> **我之前提出的知识图谱、知识卡片、验证合约等设计，是基于文献启发和 CMT50 错误归因的反向推导，但完全没有经过实验检验。它们是有道理的假设，不是已验证的方案。**
>
> **在继续任何工程投资前，应该先运行最小可行验证（1-2 周），用 CMT50 的实际数据来检验这些假设是否成立。**
