# RAG 是"蒸馏理解"还是"检索猜测"？—— 区分框架与验证设计

> 基于 CMT50 实验方法论
> 2026-06-06

---

## 一、问题的本质：两种认知机制

当 Agent 拿到教科书/论文片段后，产生正确答案的路径可能完全不同：

### 机制 A：蒸馏理解（Distilled Comprehension）

```
教科书片段 → 理解物理原理 → 内化知识表示 → 应用到新题目 → 正确推导
```

**特征**：
- 能解释"为什么"，而不仅是"是什么"
- 能处理教科书未直接覆盖的变体题目
- 推导步骤与教科书逻辑一致，但表达是重新组织的
- 错误时，错误类型是"推导细节错"而非"概念完全错"

### 机制 B：检索猜测（Retrieval Guessing）

```
教科书片段 → 模式匹配（题目关键词 ↔ 文本关键词）→ 提取看似相关的公式/结论 → 直接填入答案
```

**特征**：
- 无法解释选择理由，或理由是从文本中复制的片段
- 遇到变体题目（参数改变、条件反转）立即失败
- 答案与检索到的文本高度相似，甚至直接复制
- 错误时，错误类型是"概念完全错"或"张冠李戴"

---

## 二、为什么这个问题对 CMT50 至关重要

### 2.1 CMT50 的题目结构恰好是"反猜测"设计的

| 题目特征 | 对"检索猜测"的难度 | 对"蒸馏理解"的难度 |
|----------|-------------------|-------------------|
| 研究级题目（非教科书例题） | 🔴 高 — 无直接匹配文本 | 🟡 中 — 需要组合多个原理 |
| 参数化变体（如 N=4→N=6） | 🔴 高 — 关键词相同但答案不同 | 🟢 低 — 推导过程不变 |
| 多概念交叉（如 VMC+DQMC 混合） | 🔴 高 — 单一检索源不足 | 🟡 中 — 需要知识整合 |
| 反直觉结论（如"符号问题在某些长程相互作用中消失"） | 🔴 高 — 与常见教材表述相反 | 🟡 中 — 需要理解条件边界 |

**关键洞察**：如果 RAG 后 CMT50 准确率提升主要来自"检索猜测"，那么提升会集中在"与教科书例题高度相似的题目"上；如果来自"蒸馏理解"，提升会均匀分布在所有类型上。

### 2.2 当前实验数据已经暗示了答案

回顾 Kimi 2.6 的 CMT50 表现：

- **初始 0/50**：49 超时，说明模型"做不完"而非"不会做"
- **无超时优化后 12/50**：提升主要来自"让模型有时间做完"
- **12 个通过的题目中**：11 个是 capability-supported，1 个是 leakage-suspect

**这意味着什么？**

Kimi 2.6（无 RAG）已经能"理解"部分 CMT 题目——只要给它足够时间，它能推导出正确答案。这说明 LLM 的参数中**已经内化了部分 CMT 知识**，只是：
- 组织长推理链的能力不足（Layer 1 瓶颈）
- 推导过程中的错误无法自检（Layer 2 瓶颈）

**推论**：如果 Hakimi 的 RAG 只是让 Agent "查到了答案"，那么它的价值有限——因为 Kimi 本身已经能"做出来"。RAG 的真正价值应该是**帮助 Agent 减少推导错误**，而非**替代推导**。

## 三、区分框架：六维检测法

设计六个可操作的检测维度，每个维度都有明确的实验方法：

### 维度 1：变体题目测试（Parametric Variation Test）

**原理**：如果 Agent "蒸馏理解"了知识，它应该能处理参数变体；如果只是"检索猜测"，参数一变就失败。

**实验设计**：

```
原始题目（CMT50 #X）: Hubbard 模型 N=4, U=2, 问基态能量
变体题目 A: 相同设置，N=6, U=2
变体题目 B: 相同设置，N=4, U=4
变体题目 C: 相同设置，但问"第一激发态"而非"基态"
```

**判断标准**：

| 结果模式 | 机制判断 |
|----------|----------|
| 原始对，A/B/C 都对 | ✅ 蒸馏理解 |
| 原始对，A/B 对但 C 错 | ⚠️ 部分理解（理解了参数依赖，但未理解问题结构） |
| 原始对，A/B/C 都错 | ❌ 检索猜测（原始题恰好匹配到文本） |
| 原始错，A/B/C 都错 | — 无关（原始题也未匹配到） |

**CMT50 的可行性**：需要人工构造 10-15 组变体题目，每组基于一个通过的题目。

### 维度 2：推导步骤审计（Derivation Step Audit）

**原理**：蒸馏理解会产生"可解释的推导链"；检索猜测会产生"跳跃式结论"或"复制粘贴式答案"。

**实验设计**：

在系统提示词中增加要求：
```
For every answer, you must provide:
1. The key physical principle used (name it)
2. The mathematical step that applies it
3. A sanity check you performed
```

**判断标准**：

| 特征 | 蒸馏理解 | 检索猜测 |
|------|----------|----------|
| 物理原理命名 | 准确且与推导一致 | 模糊或从检索文本复制 |
| 数学步骤 | 逻辑连贯，有中间量 | 跳跃，直接到结论 |
| Sanity check | 与推导独立（如极限验证） | 与推导重复或缺失 |
| 错误时的表现 | 能指出哪一步可能错 | 无法解释，或坚持错误文本 |

**CMT50 的可行性**：利用已有的 stderr/stdout 日志，对通过的题目进行人工审计。

### 维度 3：干扰知识测试（Distractor Knowledge Test）

**原理**：给 Agent 提供"相关但错误"的知识片段，观察它是否能识别并拒绝。

**实验设计**：

```
题目：VMC 梯度估计量的偏差分析
检索结果 A（正确）："Reynolds 估计量是无偏的，因为..."
检索结果 B（干扰）："Reynolds 估计量是有偏的，因为..." [故意编造的假知识]
检索结果 C（无关）："DQMC 的符号问题在..." [相关领域但无关题目]
```

**判断标准**：

| 结果 | 机制判断 |
|------|----------|
| 使用 A，拒绝 B 和 C | ✅ 蒸馏理解（能判断知识质量） |
| 使用 A，也使用 B（矛盾） | ❌ 检索猜测（无法判断真伪） |
| 使用 A，也使用 C（无关） | ❌ 检索猜测（无法判断相关性） |
| 被 B 误导而答错 | ❌❌ 严重检索猜测 |

**CMT50 的可行性**：需要构建一个"污染知识库"，包含 20% 的故意错误/无关片段，然后观察 Agent 的选择行为。

### 维度 4：知识源遮蔽测试（Source Ablation Test）

**原理**：逐步移除知识源，观察 Agent 表现如何衰减。蒸馏理解的衰减是"平滑的"（知识减少 → 表现线性下降）；检索猜测的衰减是"断崖式的"（关键文本被移除 → 立即崩溃）。

**实验设计**：

```
完整知识库：CMT 教科书 + 10 篇关键论文
实验组 1：移除 50% 论文
实验组 2：移除所有论文，仅保留教科书
实验组 3：移除教科书，仅保留论文
实验组 4：仅保留目录/摘要，无正文
```

**判断标准**：

| 衰减模式 | 机制判断 |
|----------|----------|
| 线性衰减（每移除一些知识，表现下降一些） | ✅ 蒸馏理解 |
| 断崖衰减（移除某一篇后表现骤降） | ❌ 检索猜测（依赖单一关键文本） |
| 对摘要/目录也能部分工作 | ✅ 蒸馏理解（能从少量信息推断） |
| 必须有完整正文才能工作 | ❌ 检索猜测（依赖全文复制） |

**CMT50 的可行性**：最容易实施——只需控制 RAG 的知识源范围。

### 维度 5：跨领域迁移测试（Cross-Domain Transfer Test）

**原理**：蒸馏理解的知识可以迁移到相关领域；检索猜测的知识是"死"的，无法迁移。

**实验设计**：

```
训练/检索领域：凝聚态理论（CMT）
测试领域 A：量子化学（QC）中的类似方法（如 QMC 在分子中的应用）
测试领域 B：统计力学中的类似模型（如 Ising 模型的变体）
测试领域 C：完全无关领域（如流体力学）
```

**判断标准**：

| 结果 | 机制判断 |
|------|----------|
| CMT 对，QC 和 SM 部分对 | ✅ 蒸馏理解（知识可迁移） |
| CMT 对，QC 和 SM 完全错 | ❌ 检索猜测（知识不可迁移） |
| CMT 对，无关领域也"对"（幻觉） | ❌❌ 严重检索猜测 + 幻觉 |

**CMT50 的可行性**：需要构建一个跨领域 benchmark（CMT + QC + SM），约 30 题。

### 维度 6：时间-准确率曲线（Time-Accuracy Curve）

**原理**：蒸馏理解需要时间来"思考"；检索猜测是"瞬间"的（找到匹配文本 → 直接输出）。

**实验设计**：

```
测量不同时间限制下的准确率：
- 10 秒：只能做关键词匹配
- 60 秒：能做一次检索 + 简单匹配
- 300 秒：能完成检索 + 理解 + 推导
- 600 秒：能完成完整推导 + 验证
```

**判断标准**：

| 曲线形状 | 机制判断 |
|----------|----------|
| 随时间增加，准确率持续提升 | ✅ 蒸馏理解（需要时间来理解和推导） |
| 10 秒时准确率已接近饱和 | ❌ 检索猜测（匹配是瞬间的） |
| 300 秒后准确率反而下降 | ⚠️ 可能过度思考/幻觉增加 |

**CMT50 的可行性**：利用已有的多时间切片数据（45s / 300s / 无限制）。

## 四、综合验证实验设计："RAG 蒸馏 vs 猜测" A/B Test

### 4.1 实验组设计

| 组别 | RAG 内容 | 目的 |
|------|----------|------|
| **A: 完整知识组** | CMT 教科书 + 论文 + 标准结果 | 基线 |
| **B: 摘要知识组** | 仅目录 + 章节摘要 + 公式索引 | 测试"少量信息推断"能力 |
| **C: 干扰知识组** | 完整知识 + 20% 故意错误片段 | 测试"知识真伪判断"能力 |
| **D: 无关知识组** | 流体力学 + 广义相对论教材 | 测试"领域边界判断"能力 |
| **E: 无 RAG 组** | 无外部知识（纯 LLM） | 对照组 |

### 4.2 题目集设计

需要 3 套题目：

| 题目集 | 数量 | 特征 | 用途 |
|--------|------|------|------|
| **CMT50-Original** | 50 | 原始题目 | 基线对比 |
| **CMT50-Variant** | 15 | 基于通过题目的参数/条件变体 | 变体测试 |
| **CMT50-Cross** | 15 | CMT + QC + SM 混合 | 迁移测试 |

### 4.3 评估指标

| 指标 | 计算方式 | 蒸馏理解信号 | 检索猜测信号 |
|------|----------|------------|--------------|
| **准确率** | 正确题数 / 总题数 | 在 B/C/D 组中保持相对较高 | 在 B/C/D 组中断崖下降 |
| **变体保持率** | 变体对 / 原始对 | 高（>70%） | 低（<30%） |
| **干扰拒绝率** | 拒绝干扰片段的题目比例 | 高（>80%） | 低（<40%） |
| **无关领域幻觉率** | 无关知识组中"强行套用"的比例 | 低（<10%） | 高（>50%） |
| **推导完整性** | 提供完整推导步骤的题目比例 | 高（>80%） | 低（<40%） |
| **时间-准确率斜率** | (Acc_600s - Acc_60s) / (600-60) | 正且显著 | 接近零 |

### 4.4 判断矩阵

| 指标组合 | 结论 |
|----------|------|
| 准确率高 + 变体保持率高 + 干扰拒绝率高 + 时间斜率正 | ✅ 明确的蒸馏理解 |
| 准确率高 + 变体保持率低 + 干扰拒绝率低 + 时间斜率平 | ❌ 明确的检索猜测 |
| 准确率高 + 变体保持率中 + 干扰拒绝率中 + 时间斜率正 | ⚠️ 混合模式（部分理解 + 部分猜测） |
| 准确率中 + 变体保持率高 + 干扰拒绝率高 + 时间斜率正 | ✅ 理解能力强但知识覆盖不足 |

## 五、对 Hakimi 路线图的影响

### 5.1 如果验证结果是"检索猜测"为主

**调整策略**：

| 原规划 | 调整 |
|--------|------|
| Phase 2: 大规模 RAG 知识库 | **缩减** — 只保留高质量、经过验证的知识源 |
| 新增 physics_knowledge_retriever | **改为** physics_principle_index — 不返回全文，只返回"原理名称 + 适用条件 + 标准公式" |
| 依赖 RAG 提升准确率 | **改为** 依赖 symbolic_verifier + option_evidence_tracker 提升准确率 |
| 知识库更新频率 | **降低** — 静态知识库足够，动态检索引入噪声 |

**核心逻辑**：如果 Agent 只会"猜"，那么给它更多文本只会增加噪声。应该给它"更精炼的知识索引"而非"更多原始文本"。

### 5.2 如果验证结果是"蒸馏理解"为主

**调整策略**：

| 原规划 | 调整 |
|--------|------|
| Phase 2: 知识库 | **扩大** — 增加更多论文、综述、甚至原始数据 |
| 知识源范围 | 从 CMT 核心扩展到相关领域（QC、SM、AMO） |
| 检索策略 | 增加"相关原理推荐"（如"你正在做 VMC，可能需要了解 importance sampling"） |
| 长期目标 | 构建"可验证的物理知识图谱" |

### 5.3 如果验证结果是"混合模式"

**调整策略**（最可能的情况）：

| 改进 | 具体做法 |
|------|----------|
| **分层知识设计** | 第一层：原理索引（必须蒸馏理解才能用）<br>第二层：标准结果（可以检索匹配）<br>第三层：参考推导（辅助理解，不直接用于答案） |
| **强制理解验证** | 使用 RAG 后，必须通过 symbolic_verifier 或 dimensional_checker 验证，才能提交答案 |
| **知识质量评分** | 给每段检索结果标注"可靠性等级"，Agent 优先使用高等级知识 |
| **人机协同审核** | 对 RAG 通过的题目，人工抽样审核推导步骤，区分"理解"和"猜测" |

## 六、立即可实施的"最小可行验证"

不需要等待完整实验，现在就能做的 3 件事：

### 6.1 变体题目快速测试（1 天）

基于 CMT50 中已通过的 12 题，人工构造 2-3 个变体：

```
# 原始通过题示例：#27 (ED, 推导 O_n = E_n - E_{n-1})
变体 A: 问 "O_n 的物理意义是什么？"（概念变体）
变体 B: 如果能级是 E_n = n^2，O_n 的显式表达式是什么？（数学变体）
变体 C: 问 "O_n 在热力学极限下的行为"（极限变体）
```

用 Hakimi ON 模式跑这 36 题（12 原始 + 24 变体），观察：
- 原始通过率 vs 变体通过率
- 如果变体通过率 < 50% → 强烈信号：原始通过是检索猜测

### 6.2 推导步骤审计（2 天）

对 Kimi 2.6 通过的 12 题，人工阅读 stderr/stdout：

| 审计项 | 评分 |
|--------|------|
| 是否明确命名了使用的物理原理？ | 是/否 |
| 推导步骤是否逻辑连贯？ | 1-5 分 |
| 是否有与教科书不同的表达方式？ | 是/否 |
| 错误时是否能自我纠正？ | 是/否 |
| 是否出现与 gold 答案高度相似的短语？ | 是/否 |

如果"与 gold 高度相似"的比例 > 30% → 强烈信号：存在 leakage/检索猜测

### 6.3 摘要知识组快速测试（3 天）

构建一个"最小知识库"：

```
CMT 核心原理索引（仅名称 + 一句话描述 + 适用条件）：
- Variational Monte Carlo: 基于变分原理的随机采样方法。适用：多体波函数优化。
- Density Matrix Renormalization Group: 一维强关联系统的数值重正化方法。适用：低维、有限系统。
- Quantum Monte Carlo: 基于路径积分的随机数值方法。适用：平衡态统计物理。
- ...（共 20-30 条）
```

用这个"索引级"知识库跑 CMT50，对比完整知识库：
- 如果准确率下降 < 20% → 信号：Agent 能从少量信息推断（蒸馏理解倾向）
- 如果准确率下降 > 50% → 信号：Agent 依赖全文检索（检索猜测倾向）

## 七、哲学层面的结论

### 7.1 "蒸馏理解"和"检索猜测"不是二元的

实际 Agent 行为是一个光谱：

```
纯猜测 ←————————————————————→ 纯理解
  |           |           |
  |    混合模式（最可能）    |
  |           |           |
关键词匹配   模板填充    原理重组    创造性推导
```

CMT50 的 50 题中，可能：
- 20% 是"纯猜测"（恰好匹配到类似例题）
- 50% 是"混合模式"（部分理解 + 部分匹配）
- 30% 是"纯理解"（需要真正推导）

### 7.2 对 Agent 设计的启示

| 目标 | 设计原则 |
|------|----------|
| 最大化"蒸馏理解" | 提供**结构化知识**（原理索引、公式图谱）而非**非结构化文本**（论文全文） |
| 最小化"检索猜测" | 强制**验证闭环**（每步必须有 symbolic/dimensional 验证） |
| 检测"混合模式" | 使用**变体题目**和**干扰知识**作为常规测试手段 |
| 提升"纯理解"比例 | 增加**推导深度要求**（必须展示中间步骤，禁止直接给结论） |

### 7.3 对 CMT50 评估的启示

当前 CMT50 的"通过/失败"二元评分不足以区分两种机制。建议增加：

| 新增评估维度 | 目的 |
|-------------|------|
| **变体题目集** | 检测"参数敏感的理解" |
| **推导步骤评分** | 检测"可解释的推理" |
| **干扰知识抗性** | 检测"知识真伪判断" |
